# Tencent/MING and Youdao/MING CUDA engines

## Current validation scope

Tencent is packaged and installed on olarestest003. The development image `s2st-tencent-dev-20261120-9` completed all 20 original RealSI recordings both with ASAP upload and with 1x realtime input: 20/20 successful in each cohort, no synthesis retries, all source samples consumed. Independent generated-audio ASR and automatic text/audio scoring ran only after timed inference released the GPU. This is a public-data local benchmark, not a reproduction of Tencent's GEMBA 84.7 score or an untouched held-out set.

The ASAP input-weighted total S2ST RTF is 0.7565 (worst recording 0.9285). Realtime input has a 17.20-second maximum FIFO playback gap and 25.53-second maximum playback tail. Source audio and exact arrival-paced context clips are provided to distinguish source pauses from additional waiting; coarse reference segments alone cannot establish continuous speech. Throughput and protocol completion have passed; uninterrupted listening has not. The complete original source, raw model translation, actual delivered PCM and arrival-paced replay are retained. No silence is removed to disguise waiting.

Youdao development image `s2st-youdao-dev-20261120-6` is published for AMD64 and ARM64 and installed on olarestest003. Four controlled MING inputs match the frozen Tencent PCM exactly. Actual nonstreaming HTTP, HTTP streaming and WebSocket requests passed in both directions, including observed 2000/4000 ms ASR routing, complete input drain, zero synthesis/translation retries, active disconnect cleanup and a fresh recovery request. The image6 scheduling pilot is not accepted: education retained exact2s source/MT text atRTF0.658, but sport was1.499 and the live health request failed with an internal HTTP ReadError. These results are retained, not counted as a passing benchmark. Complete scores and uninterrupted-listening acceptance are not yet asserted. Only zh2en and en2zh are in scope. Intel is unimplemented and must use a separate OpenVINO backend behind the same session contract.

## Product boundary

One application exposes one S2ST engine. Its internal translation, recognition and speech services are owned implementation details, not separately scheduled Olares applications. Tencent owns Hy-SimulMT GGUF plus MING; Youdao owns R2T2, T3PO GGUF and the exact same MING implementation and settings.

All weights must already exist in llm-init's Common cache. Serving never downloads weights. Readiness waits for model loading, placement and health checks. Concurrency is one session. Worker death, abnormal native EOS, incomplete source consumption or uncommitted translated text fail the request. There is no hidden synthesis retry or replacement by reference text.

## Shared MING contract

The downstream uses source-speaker-only conditioning with the official CAMPPlus CUDA encoder, CFG 1, temperature 0, seed 0, native text preparation length 24 and normal EOS checks. Generated speech is never fed back as conditioning. English receives complete words. Unambiguous sports scores are rendered for speech in sports context; the raw translation remains intact. Dates and decimal values are not rewritten by this score renderer.

Tencent supplies committed incremental text directly to the shared Speech implementation. No extra complete-sentence gate is required. The actual full Tencent cohorts produced 528 MING requests with ASAP input and 1911 with realtime input; concatenated request text exactly matches every corresponding raw translation, including whitespace. All native fragments ended normally. These checks do not prove pronunciation or audible completeness; both cohorts were independently transcribed and remain available for listening.

A causal bounded playout queue applies pitch-preserving rate adjustment. Raw synthesis and delivered audio are distinct evidence. The arrival-paced WAV reconstructs the recorded FIFO schedule; it is not a physical sound-card recording. Nonstreaming output contains the complete audio without artificial delivery-wait silence.

## Required Tencent native and shared transport adaptations

1. The official native CLI gains bounded PCM16 input, telemetry, private-FIFO session ownership and a shared-library lifecycle entry. Model arguments, encoder, decoder, sampler, prompt and turn sizes remain unchanged. Two original unspliced 40-second recordings in opposite directions match standalone native token IDs, UTF-8 output, consumed samples, audio turns, EOG values and context positions. Timing is excluded from that equivalence assertion.
2. MING and the native entry share one GPU PID. The first installed two-process candidate exposed alternating roughly ten-second GPU waits. This lifecycle change retains the Olares preload and scheduling policy. Native cleanup and lock release finish before terminal success is acknowledged; cleanup failure is explicit.
3. WebSocket upload drains valid frames to a private temporary file bounded by the 900-second mono PCM16 limit (28.8 MB). The native reader still consumes samples in order, and speaker conditioning advances with native consumption. EOF drains all input; disconnect cancels work and closes the spool.
4. Nonstreaming HTTP establishes response headers before long model work, then returns one complete JSON/WAV result. Errors after headers return an explicit terminal error without successful audio; callers must inspect the terminal type. NDJSON and WebSocket remain incremental.

The image8 full ASAP cohort failed one long WebSocket upload because prolonged inference backpressure hit Linkerd's TCP user-timeout. No Pod restart or OOM occurred. That 19/20 cohort remains failed. A separate HTTP diagnostic and then a fresh image9 474-second WebSocket regression succeeded; image9 subsequently completed the two new full 20-recording cohorts above. No old failed row was retried into a passing old cohort.

## Selected Youdao adaptations

The selected deployment retains official feed/flush and autoregressive recognition. Its rolling audio/text ledger uses actual sample counts, and EOF delivers residual PCM before original finalization, including the empty-buffer case. Official CUDA neural VAD remains. Added EOS padding is separately logged and excluded from the source denominator.

Source number tails, including Chinese scales, digit/scale mixtures and decimal points, wait for the actual remaining number or unit before append-only MT. No source text is rewritten; EOF flushes all remaining characters. This prevents a reproduced split of 七十万 into 七十 and 万 that had caused a tenfold magnitude error. Physical VAD markers never force textual commitment: the original ASR reset is the final-text acknowledgement. A removed early-flush adapter had submitted half-words and half-numbers even with reset=false. The original VAD neural computation remains intact. The age of pending source text, rather than repeated ASR arrivals, controls the bounded translation deadline. Incremental T3PO SSE preserves the official prompt and latency policy. Its OpenAI minimum-one-token setting is adapted to llama.cpp's nonempty grammar, and repetition-penalty spelling is translated. Abnormal completions fail explicitly. A foreign-script fragment is preserved as raw model output and recorded as a quality warning, as for Tencent; it is not silently rewritten or converted into a transport failure. Older wrong-language retry experiments are not selected.

The extra Youdao-only complete-sentence gate and speech-oriented prompt are removed. ASR delivery retains actual rolling audio/text sample alignment, final residual drain and explicit 500 ms EOS padding. The selected upstream translation policy is the author's native/balanced mode. The current image6 candidate restores 2000 ms English ASR submission increments and retains 4000 ms Chinese increments. Its optional ASR overlap changes only execution scheduling; native MT and MING remain mutually serialized. The default is still serialized ASR. No recognition neural step, precision or MING setting changes. Original recognition, native MT policy and shared MING remain unchanged; the language override remains available through ENGINE_ARGS, never benchmark-text detection. Global warmup and all original neural steps remain. Installed requests in both directions verified the actual observed ASR input sizes, not just the requested flags. Only trailing English function words are held until the next translated content. Final speech text is checked against canonical translation using the pinned official join function; explicit inter-completion word-boundary spaces are retained and their input hash and comparison scope are recorded. EOF flushes any remainder. This upstream boundary addresses a reproduced native-EOS failure on an isolated dangling preposition. It does not change MING or add retries.

The recognizer uses its official HF neural forward through an audited dispatch of the original streaming algorithms. A private Transformers 4.57.6/tokenizers 0.22.2 namespace isolates ASR from MING's unchanged Transformers 4.46.3/tokenizers 0.20.3 stack. Four controlled MING outputs match exact PCM both with the namespace and with all three GPU residents loaded. The installed product also passed these four controlled PCM comparisons. Full original live health/sport/science development regressions and full20 quality assessment are separate evidence; a build/import pass is not a neural acceptance result. The product worker owns ASR/VAD, the original native T3PO server and unchanged MING in one GPU PID; the separate bridge process is CPU only. Older four-process prototypes are not the selected deployment.

The TempoStream dependency repair adds the already validated imageio-ffmpeg version and executes real PCM conversion during image build.

The experimental PTL chart remains version 0.1.0 with llm-init v1.7.26, Common Hugging Face storage and Common run state. No formal submission is made. Nonstreaming, incremental delivery, input drain, invalid frames and disconnect cleanup have automated coverage; installed Youdao route and disconnect checks passed in both directions. Inference-related session initialization is included in per-request total RTF. The installed full20 cohorts use a warm service and empty source-reference/speaker-embedding caches before each cohort; a clean-cache service cold-start benchmark is not claimed.

## Installed Youdao readiness and cache checks

The official speech bridge sends `loading` records for translation and ASR before `init_ok`. The adapter waits for that acknowledgement on the same connection under one initialization deadline and does not feed PCM early. Real initialization errors still fail the request; loading progress is not an inference retry.

Actual GPU placement is verified after an uncached speaker extraction. CAMPPlus executed 281 weighted nodes on CUDA and zero weighted CPU nodes; R2T2 parameters and nonempty model buffers and the original neural VAD were CUDA resident. The native T3PO loader reported 49/49 layers offloaded and a CUDA0 model-weight buffer. Host NVML PID and container audit PID are linked by the process namespace PID chain. A cache hit with zero profiled weighted executions is insufficient evidence, so owned diagnostic reference and speaker caches are archived through Olares Files before this check. No MING implementation or setting is changed.

The native core loader's INFO callback maps to verbosity 4 in the pinned upstream logger; ordinary server INFO uses 3. LOG_LEVEL=info therefore requests native verbosity 4 to retain placement evidence; decoder, sampler and MING settings are unchanged.

llm-init v1.7.26 forwards repeated `--include` flags, while its actual HF CLI retains only the last pattern. The chart downloads the complete R2T2 repository, containing one weight file and its small configuration/tokenizer files, and declares the two VAD files as separate frozen HF sources. No extra weight version is downloaded. The PTL chart keeps the standard system HF endpoint. For the isolated installation experiment, a temporary chart copy selected a read-only LAN endpoint serving only SHA/Git-blob-verified public files at the same pinned revisions; llm-init still performed all Common writes.

ENGINE_ARGS `--overlap-asr` is an opt-in Youdao scheduling control. Readiness records the worker flag and verifies that actual streaming ASR calls bypassed only the global GPU-stage queue; MT and MING still use the unchanged mutual-exclusion guard. The benchmark freezes this flag explicitly. Six installed route checks, disconnect cleanup and four controlled PCM comparisons passed on image6. These gates do not replace the full original-recording benchmark.
